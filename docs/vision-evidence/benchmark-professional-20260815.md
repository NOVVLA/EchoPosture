非推断、非理论峰值。

## 权重选型基准

方法：合成帧 640×480（固定种子，不开摄像头），每权重 3 帧预热 + 12 帧计时，nearest-rank 百分位。
目标预算 P95 ≤ 50 ms（对应 ≥20 Hz）。

| 权重 | P50 | P95 | 约合 | 是否达标 |
| --- | --- | --- | --- | --- |
| `yolo26l-pose` | 16.8 ms | 17.5 ms | 59.6 Hz | 是 |
| `yolo26x-pose` | 16.8 ms | 20.8 ms | 59.4 Hz | 是 |

**选中 `yolo26x-pose`**（达标者中的最大权重）。

值得注意：l 与 x 的 P50 实际相同，说明本设备上瓶颈不在算力，选最大权重不付出吞吐代价。这个结论
只适用于本参考设备，其他 GPU 必须重跑基准（这正是自动选型存在的理由）。

## 持续推理

预热 5 帧后连续 40 帧，合成帧 640×480：

| 指标 | 值 |
| --- | --- |
| P50 | 16.9 ms |
| P95 | 20.1 ms |
| 吞吐 | 约 59.3 Hz |
| 峰值显存 | 0.35 GB |

峰值显存远低于 11.9 GB，本设备上 x 的 OOM 风险可排除（OOM 降级链仍保留，供显存更小的设备使用）。

## CUDA 与 CPU 数值一致性（Blackwell 正确性）

同一权重、同一帧，分别在 `cuda:0` 与 `cpu` 上推理，按 bbox 左边界排序后逐点比较。
测试图为 Ultralytics 自带素材（`bus.jpg`、`zidane.jpg`），不引入任何新的人像资产。

| 图像 | 检出人数 GPU/CPU | 关键点偏差 max / mean | bbox 偏差 max / mean |
| --- | --- | --- | --- |
| `bus.jpg` | 4 / 4 | 0.1135 px / 0.0108 px | 0.0430 px / 0.0088 px |
| `zidane.jpg` | 2 / 2 | 0.0415 px / 0.0097 px | 0.0610 px / 0.0294 px |

计划设定的门槛是 <1 px，实测最大偏差 0.11 px。**sm_120 上的推理数值正确性通过**。

上测得接近值再调整。

## 可用性探测

真机实测：三档均判定为可用，耗时 **9.63 ms**（预算 50 ms），且探测过程**未导入 torch**
（`'torch' in sys.modules` 为 `False`）。

## 升级 CUDA torch 对 Standard mode 的影响

同一运行时上重测标准模式（仍 `device="cpu"`）：

| 阶段 | 升级前（计划文档记录） | 升级后实测 |
| --- | --- | --- |
| 冷导入 `ultralytics` + torch | 1.6 s | **4.47 s** |
| `yolo26n-pose.pt` 权重加载 | 3.0 s | 0.11 s |
| warmup 首帧 | 0.06 s | 0.14 s |
| CPU 单帧推理 P50 | 23 ms | 25.0 ms（P95 42.0 ms） |

冷导入变慢约 2.8 s，是 CUDA 构建原生库更大的直接代价。但本次测量中权重加载只用了 0.11 s，
两项相抵后总启动时间反而更短。**需要注意**：0.11 s 是文件系统缓存命中的结果，与升级前记录的 3.0 s
不是同等条件（后者可能是冷盘），因此不能据此声称"升级让启动更快"。可以确认的是：冷导入确实变慢了，
CPU 推理速度基本不变。

`docs/STANDARD_MODE.md` 中引用的旧数字应以本表为准。
