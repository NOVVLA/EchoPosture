# ADR-0002：姿态检测的科学性改进机会

- 状态：Accepted for implementation
- 日期：2026-08-11
- 关联：ADR-0001, `vision_test.py`, `vision_tracking.py`, `tray_app.py`

## 背景

当前姿态检测系统基于阈值匹配(`HighPrecisionPostureAnalyzer`)判定风险。
系统运行可靠,但在科学性、个体化和干预有效性上存在可改进空间。本文档
记录了对现有判定链的审计发现,提出改进方向,并标注哪些改动在当前条件
(正面单目、MediaPipe、CPU、15fps)下可行。

## 审计发现

### F1. 测量能力边界未明确声明

**现状:**
项目命名为"驼背检测",但正面单目摄像头无法测量临床金标准:
- CVA(颅椎角):需要侧面视角看 C7 棘突到耳屏连线与水平夹角
- Cobb 角:胸椎曲度,正常范围约 20–45°,需要 X 光或侧面深度信息

当前五个判定维度(头部转向、距离、肩宽、肩部不对称、躯干侧倾)主要测量
屏幕距离、头部旋转和侧向倾斜,而非驼背本身(胸椎屈曲+头前伸)。

**证据:**
- `_distance_score`: 估算眼距反推距离 (`vision_test.py:652-687`)
- `_head_turn_score`: 眼宽比 + 头部比例 (`vision_test.py:689-737`)
- `_shoulder_width_score`: 肩宽像素比 (`vision_test.py:778-803`)
- `_shoulder_asymmetry_score`: 肩高差角度 (`vision_test.py:749-776`)
- `_trunk_lean_score`: 肩髋水平偏移角 (`vision_test.py:805-830`)

**问题:**
头前伸和胸椎屈曲只能通过间接信号推断(肩宽变窄+眼距变大),但这些
信号同时响应其他动作(整体靠近、侧倾、旋转),造成多因一果的混淆。

**可用但未用的正面信号:**
1. **头相对躯干前移**: `interpupillary_px / shoulder_width_px` ∝
   躯干深度/头深度。全身靠近时比值不变,唯有头前伸时上升。此比值已在
   `_profile_ratios` 计算(`vision_test.py:346-354`),但只用于换人
   比对 `_profile_check_decision`,未用于姿态判定。

2. **躯干塌陷**: `torso_height_px / shoulder_width_px`,塌坐时下降。
   同样已计算但未用于姿态判定。

3. **耳-肩相对位置**: MediaPipe Pose 输出耳朵关键点(7/8),但当前
   只取 5 个身体点(`vision_backend.py:163-172`)。耳到肩的垂距
   (归一化)是正面视角下头前伸的直接代理。

**建议:**
明确声明测量边界;将已计算的 `face_shoulder_ratio` 和
`torso_shoulder_ratio` 接入姿态判定;增加耳朵点提取。不声称测量
CVA 或脊柱绝对角度。

### F2. 校准基线缺乏构念效度

**现状:**
`set_baseline_from_sample` 用**单帧**定基线(`vision_test.py:230-262`),
不检查该帧的姿态质量。若用户在已驼背状态下点"校准",系统将驼背记为
"正常",此后永远不会报警。

**证据:**
```python
# vision_test.py:230-256
def set_baseline_from_sample(
    self,
    sample: VisionSample,
    calibrated_distance_cm: Optional[float] = None,
) -> bool:
    if (
        sample.interpupillary_px is None
        and sample.signed_shoulder_diff_px is None
        and sample.trunk_lean_deg is None
    ):
        return False  # 唯一的质量检查是"至少有一个指标"
    # 无姿态质量判断,直接采用当前帧作为基线
    self.baseline = PostureBaseline(...)
```

**问题:**
校准的参照系是任意的。这不是精度问题,而是**构念效度**问题——测出的
"偏离量"不指向任何健康相关的东西,因为基线本身可能就是不良姿态。

**扩展问题:**
`PostureBaseline` 只存均值(`vision_test.py:124-133`),不存方差和
样本量。单次测量的随机误差会永久污染基线,且系统无法区分"真实变化"
和"测量噪声"。

**建议:**
- **双锚点校准**: 请用户分别采集"挺直"和"故意塌陷"两段,记录每个
  人的姿态动态范围。判定从"超过 6°"改为"处于你自己范围的 70% 塌陷处"。
  性价比最高,一次性解决个体解剖差异(先天高低肩、体型、镜头位置)的
  系统性误判。

- **多帧 + 质量门**: 校准改为采集 N 帧(如 20 帧),同时记录 mean、std、n。
  若 std 过大则拒绝并要求重做,避免抖动或短时异常姿态污染基线。

### F3. 缺少测量标准误和最小可检测变化

**现状:**
系统不知道自己的测量噪声地板。临床测量学中,SEM(测量标准误)和
MDC(最小可检测变化,约 1.96×√2×SEM)用于判断一个变化是否真实。
低于 MDC 的变化在统计上与测量噪声无法区分。

**估算(待实测确认):**
640×480 分辨率下肩宽约 150–200px,`_shoulder_asymmetry_score`
最低档 3°(`vision_test.py:773`)对应肩高差约 8–10px。MediaPipe
关键点的帧间抖动可能就在此量级,意味着最低档可能报告的完全是噪声。

**证据:**
`PostureBaseline` 无 `std` 字段,无法计算 SEM 或 MDC。所有阈值
(3°/6°/10°、18px 肩宽差、0.45/0.65 眼宽比)均为手工设定,未经
噪声地板验证。

**可验证的改进:**
采集 200 帧静止样本,计算各指标的 std,推算 MDC,删除低于 MDC 的
阈值档位。这是将"科学性"从主张变为可验证事实的最低成本方法。

---

### F4. 阈值函数不连续,造成边界不稳定

**现状:**
所有评分函数使用阶梯函数。肩部不对称 5.9° 得 8 分,6.1° 得 17 分
(`vision_test.py:770-775`)。同一姿势在边界抖动时,分数跳 9 分,
足以穿越 `risk_start_score=35`,让 `_update_sustained_risk` 的
计时器反复起停。

**证据:**
```python
# vision_test.py:767-776 (肩部不对称示例,其他四个维度同理)
if angle_deg > 10.0:
    return 25.0
if angle_deg > 6.0:
    return 17.0
if angle_deg > 3.0:
    return 8.0
return 0.0
```

**问题:**
判定对输入不连续,在科学上无依据(生理变化连续,阈值人为),在工程上
导致不稳定。

**建议:**
换用连续函数(分段线性或 logistic),配合双阈值滞回(hysteresis)
处理噪声信号的开关抖动。

---

### F5. 五维独立求和,实际强相关

**现状:**
`instant_score` 为五项直接相加(`vision_test.py:426-433`):
```python
instant_score = min(
    100.0,
    head_turn_score
    + distance_score
    + shoulder_width_score
    + shoulder_score
    + trunk_score,
)
```

**问题:**
求和隐含独立性假设,但五个维度强相关。一次前倾同时命中:
- `distance_score`: 35 分(眼距变大 → 距离近)
- `shoulder_width_score`: 25 分(肩宽像素变小)
- `trunk_lean_score`: 17 分(可能伴随躯干前倾)
- 总计 77 分,一个物理成因计三次

**具体案例:**
用户后退 30%,肩宽像素下降至 0.7 倍基线,触发 `shoulder_width_score`
12 分(`vision_test.py:801`)。同时 `_distance_score` 因 >120cm
给 18 分(`vision_test.py:681-683`)。一个"往后靠"动作被当作两份
独立证据。

**建议:**
姿态模式判别(前倾/侧歪/旋转/塌陷/过近),一个成因只归一次;或使用
马氏距离,协方差矩阵自动处理相关维度。

### F6. 距离归一化不完整

**现状:**
`_shoulder_width_score` 直接比较肩宽像素比(`vision_test.py:793`):
```python
width_ratio = sample.shoulder_width_px / self.baseline.shoulder_width_px
```
用户后退时肩宽像素下降,被误判为"驼背"(肩宽变窄)。

**对比:**
`_shoulder_asymmetry_score` 用 `atan2(delta, shoulder_width)`
(`vision_test.py:766`),分子分母同单位,比值尺度不变——这是全文件
设计最好的指标。

**解药已存在但未使用:**
`_profile_ratios` 计算的 `interpupillary / shoulder_width`
(`vision_test.py:351`)是尺度不变量,正好消除距离混淆,但它只喂给
换人比对,完全没进姿态打分。

**建议:**
将 `face_shoulder_ratio` 和 `torso_shoulder_ratio` 接入姿态判定,
替代当前的绝对肩宽比。

---

### F7. 置信度信息被丢弃

**现状:**
MediaPipe 输出 `visibility` 只当二值门用:`< 0.5` 直接返回空值
(`vision_test.py:1120, 1133, 1142`)。过门后,0.51 和 0.99 的
肩膀权重完全一样。

**证据:**
`Keypoint.confidence` 字段存在(`vision_backend.py:18`),但
`observation_from_sample` 一律填默认值 1.0(`vision_backend.py:193`):
```python
keypoints = tuple(Keypoint(point[0], point[1]) for point in body_points)
# 第三个参数 confidence 省略,默认 1.0
```

**建议:**
将 `visibility` 传入 `Keypoint.confidence`,低置信度的关键点降低
其在评分中的权重；目标明确但质量不足时输出 `OBSERVING` 并暂停暴露，
目标归属或可测性不成立时输出 `UNKNOWN`，不得用 `WATCH` 代替不确定状态。

---

### F8. 时间模型与严重度解耦

**现状:**
`bad_sustain_seconds=8` 对所有严重度一视同仁(`vision_test.py:364`)。
30° 的塌陷和刚过线的抖动都等待 8 秒。人因学上是剂量-反应关系,
越严重应越快升级。

**更严重的问题:**
`risk_clear_seconds=4` 一过就清零(`vision_test.py:865-868`):
```python
if smoothed_score < 25.0:
    self._risk_started_at = None
    self._last_risky_at = None
    return 0.0
```
每 5 秒塌 3 秒的人,累计不良暴露很大,但永远攒不满连续时长,一次都不会
被提醒。

**建议:**
换成**带衰减的累积暴露量**(分数对时间积分),间歇模式自然被捕捉。
给恢复和微休息**记正账**——短时频繁休息减少不适是有人因学支持的,
而现在系统只有惩罚没有信用。

---

### F9. 输出量纲不诚实

**现状:**
`risk_score` 是 0–100 的无量纲和,外观暗示某种标定过的严重度,
但实际上是五项任意相加的结果,无解释性。

**证据:**
`tray_app.py:759` 的干预门槛 `risk_score < 45 or sustained < 12`
与分析器内部的 35/8/30 各自独立,没有一致性验证。

`_basic_mode_evaluate` 在 `vision_test.py:469` 硬编码 BAD=60 分,
这是为回退路径伪造的分数,没有实际依据。

**问题:**
用户无法理解"risk_score=62"意味着什么,无法验证其正确性,也无法
与自身感受对应。

**建议:**
主指标换成**有单位、可解释**的量,如"今日累积静态负荷 42 分钟",
或"当前姿态持续 8 分钟"。用户能理解、能验证,且不声称超出证据的东西。

---

### F10. 缺少场景与活动上下文

**现状:**
打字、开会、看手机、伸手拿杯子,跑同一套阈值。`_head_turn_score`
检测不到眼距时直接给 35 分(`vision_test.py:703`)——喝口水就算
高风险。

**可用但未用的信号:**
`_Track.velocity` 已在计算(`vision_tracking.py:429`),关键点速度
和抖动可以直接当活动度代理。大幅短时位移 = 取物,不是姿势崩坏;
头朝下 + 躯干静止 = 看手机;头朝下 + 眼距正常 = 看键盘。

**建议:**
用已有运动信号区分场景,而非增加更多阈值。

---

### F11. 摄像头几何假设无监测

**现状:**
所有比例量假设摄像头不动、焦距不变、IPD 校准有效。笔记本翻盖角度
变化会让基线静默失效,无检测机制。

**自洽检查方案:**
`torso_shoulder_ratio` 在同一人身上应近似恒定(骨架比例不变)。
它突变而其他量不变,更可能是镜头动了而不是人变了。

**建议:**
用不变量(如躯肩比)做漂移检测,超过阈值时标记"校准可能失效"。

---

### F12. 无反馈闭环,常数无法改进

**现状:**
系统不记录 alert 是否被采纳或忽略。所有阈值纯手工,无验证途径。

**证据:**
`docs/vision-evidence/` 目录存在但仅为换模型准备,不服务于调判定。

**建议:**
本地记录 `(features, score, alert, 用户反应)`,先让阈值能按人拟合,
有标注后再谈学习型权重。升级模型不会修好判定层本身有偏的问题。

## 人因学与干预有效性

### F13. 干预目标应转向剂量学

**科学依据:**
人因工程学共识重心从"某个姿势有害"转向"**长时间静态负荷有害**"。
相关机制假说(如 Cinderella 假说:低阈值运动单元在长时间低强度静态
工作中持续激活,是慢性肌肉疼痛来源)和"最好的姿势是下一个姿势"这类
经验共识都指向:**持续时长和姿势变化度,比瞬时几何形态更能预测不适**。

**关键优势与边界:**
持续时长和活动变化可以作为独立于姿态几何的暴露上下文，但当前兼容模式
只能从目标人体框中心平移和框尺度变化估算“低轨迹活动”。它仍受镜头移动、
检测框抖动、遮挡、视角和目标关联质量影响，也不能证明四肢或身体内部完全
没有活动。因此该信号不需要医学角度标定，却仍需要稳定目标、时间戳、质量门控
和观测连续性；只能作为有上限的综合风险修正，不能当成姿态异常或临床静止量。

**建议:**
将姿态偏离和低活动暴露分开显示。只有在真实数据验证测量可靠性后，才可把
“低轨迹活动 X 分钟”进一步解释为“保持同一姿势 X 分钟”；当前实现不得越过
这一证据边界。

---

### F14. 警报疲劳风险

**临床证据:**
误报率高或频率过密的警报会被系统性忽略,最终等于没有干预。
"检测更准"和"干预有效"是两件事,后者需要单独机制。

**建议:**
1. **不确定就弃权**: 目标明确但低置信度时输出 `OBSERVING`，归属或测量不可用时输出 `UNKNOWN`；`WATCH` 只表示已检测到姿态偏离
2. **警报预算和冷却期**: 防止频繁打扰
3. **记录忽略率**: 唯一能本地量化干预有效性的指标

## 改进方案分级

### 第一批:高收益、低成本、不需要新数据

| 改动 | 科学收益 | 实现成本 | 依赖 |
|------|----------|----------|------|
| 双锚点校准 | 解决构念效度和个体差异 | 中(改数据结构+UI) | 无 |
| 基线存方差 | 区分真实变化和噪声 | 低 | 无 |
| 累积暴露量 | 对齐人因学剂量证据 | 低 | 无 |
| 主指标改有单位量 | 输出可解释 | 低 | 无 |
| 两比值接入打分 | 消除距离混淆 | 低 | 无 |
| 阶梯改连续函数 | 消除边界不稳定 | 低 | 无 |

### 第二批:中等工作量

| 改动 | 科学收益 | 实现成本 | 依赖 |
|------|----------|----------|------|
| 置信度传播 | 不确定性表达 | 低-中 | 无 |
| 噪声地板实测 | 验证阈值有效性 | 中 | 需采集静止样本 |
| 镜头漂移检测 | 防止基线静默失效 | 低 | 无 |
| 恢复记正账 | 改善依从性 | 中 | 无 |

| 改动 | 科学收益 | 实现成本 | 依赖 |
|------|----------|----------|------|

## 可验证性:如何证明科学性

### 可立即验证的(无需外部金标准)

1. **测量可靠性:**
   - 同一用户重复校准 N 次(如 10 次),计算 SEM 和 MDC
   - 静止 200 帧,计算各指标 std,推算噪声地板
   - 报告:"肩部不对称 SEM=1.2°, MDC=3.3°,当前最低阈值 3° 低于 MDC"

2. **不变量自检:**
   - `torso_shoulder_ratio` 在同一人短期内应稳定,计算其 CV
   - 报告:"躯肩比 CV=4.2%,用于镜头漂移检测"

3. **内部一致性:**
   - 验证 `tray_app.py:759` 的 45/12 门槛与分析器 35/8/30 的关系
   - 报告干预触发率、误报率(通过忽略日志)

### 需要外部参照的(现阶段不做)

- 效度:与 CVA、Cobb 角、主观不适评分的相关
- 临床意义:干预是否减少实际疼痛或不适

**建议表述:**
"本系统的测量可靠性已验证(SEM/MDC 已知),效度未经外部金标准验证,
不做健康主张。输出为个体内变化指标,用于自我监测。"

---

## 明确不应做的

1. **不声称测量 CVA 或脊柱绝对角度**: 正面单目做不到,标了就是不诚实。

2. **不用重模型(AdaFace/YOLO)解决当前问题**: Phase 3–5 的模型升级
   解决身份和多人问题,不会修好校准基准无效、剂量学缺失、量纲混乱。
   更好的姿态模型喂给有偏的判定层,结果仍然有偏。

3. **不继续增加阈值档位**: 多情况需要的是上下文区分(打字/开会/取物),
   而不是更细的阈值。

---

## 决策

**Accepted for implementation:**
本次实现接受第一批改动，并将生产入口切换到显式分阶段的双锚点流程：

1. 可见倒计时完整 5 秒只收集用户希望长期采用的舒适坐姿；倒计时关闭后提示用户可以放松，约 1 秒过渡不采样，再静默收集约 5 秒自然放松姿势。放松阶段有效样本不足时最多延长 2 秒；每个锚点至少需要 5 个有效单人样本。
2. 每个特征保存 mean/std/n/SEM/MDC/CV；两个锚点只定义有序的个人正常范围。相同或相近锚点仍然有效，不以分离度超过噪声作为校准门槛；特征只因任一阶段不足 5 个有效值而停用。
3. 姿态偏离使用脸肩比、躯干肩比、可用的耳肩比、肩部不对称角、躯干侧倾角和头-躯干二维投影夹角，并按物理证据组去重。躯干侧倾角与头-躯干夹角共享肩-髋投影轴，归入同一投影轴通道，不能互相伪造第二票；肩线相对骨盆线的不对称仍是独立侧向通道。
4. 干预以真实时间积分的等效静态姿态暴露为主，恢复按指数衰减；运动、目标不确定、低质量和镜头参考变化期间暂停。明确区分 `MOVING`（检测到活动）、`ADJUSTING`（短暂探身或姿态调整）、`OBSERVING`（目标明确但该帧不计暴露）与真正无法测量/归属的 `UNKNOWN`。`WATCH` 明确表示已检测到姿态偏离；只有达到 `0.70` 警报滞回后才积分等效高偏离秒数。低轨迹活动从 60 秒起线性增加综合风险、180 秒达到上限 `0.12`；它不改变 `posture_deviation`，不能单独进入 `WATCH/BAD/CRITICAL`，也不能单独生成姿态暴露。运动、目标不确定、低质量或超过 2 秒的观测缺口会重置该计时。
5. 舒适与自然放松两个锚点都是用户明确接受的姿势，两者的有序均值之间形成个人正常姿态带，偏离度均为 `0.0`。校准成功后先用目标锁定后的运行时样本稳定复验约 2 秒，复验期间输出 `OBSERVING`、偏离度为零并暂停暴露。普通单项漂移仍需独立证据佐证并持续约 2 秒才进入 `WATCH`；但高质量、远超个人范围且对应合理单一物理通道的强证据可以单独进入 `WATCH`，包括显著躯干侧倾、头-躯干投影错位、肩-骨盆不对称、头/躯干前向通道极端变化和极端持续头部方向。该例外仍不能跳过 12/30 秒暴露门槛。确认期作为 `ADJUSTING` 显示且不补算暴露。
6. SEM/MDC 继续作为可审计统计和噪声依据，但不再用于强迫两个姿势分离。运行时单帧测量噪声带取 MDC、`3.0 ×` 锚点内标准差和保守特征分辨率地板（归一化比例 `0.025`、角度 `2.5°`）中的最大值；在此基础上再增加独立的自然动作死区（归一化比例 `0.05`、角度 `3°`），用于吸收呼吸、探身和坐姿调整，不把用户动作伪装成传感器噪声。小幅单项变化按正常变化处理。超出测量噪声和自然动作死区后，比例特征以固定 `0.10`、角度特征以固定 `10°` 映射连续偏离，完全独立于两锚点间距。全身同比例尺度变化保持可测量；肩宽只有在缺少原始分子变化却制造比值佐证时才停用该帧。这些数值属于暂定产品可靠性和交互参数，不是生理标准。
7. 新增的二维投影契约只描述摄像头图像平面内的几何关系：`projected_trunk_axis_deg` 是肩中心到髋中心轴相对图像竖直方向的有向角；`projected_head_trunk_angle_deg` 是鼻尖到肩中心轴与肩中心到髋中心轴之间的最小有向夹角。评分只比较同一用户、同一后端校准范围之外的变化。它不是 CVA、Cobb 角、三维脊柱曲率或临床脊柱倾斜角；摄像头横滚、透视、离平面运动、关键点误差和遮挡均会影响它。`projected_trunk_axis_deg` 用于审计显示；其姿态评分与既有 `trunk_lean_deg` 共用同一肩-髋轴，不重复计分。
8. 超过 `2.0` 秒的观测缺口不补算为连续暴露；已有暴露仍按恢复模型衰减，但当前偏离退出观察滞回后立即显示 `GOOD`，不因历史残余暴露继续显示 `WATCH`。
9. 所有数值均为 `posture_science.py` 中的产品可靠性和交互策略参数。它们不表示医学角度、生理标准或经临床验证的剂量阈值。

实现位置：`posture_science.py`（统计、连续评分、暴露），`vision_test.py`
（样本/分析器），`vision_worker.py`（双阶段采样），`vision_tracking.py`
（运动状态），`tray_app.py`（生产入口与干预门槛）。现有
`set_baseline_from_sample()` 保留为显式 legacy 调试/自测路径；生产分析器
使用 `require_dual_anchor=True`，不能由单帧直接进入科学模式。

可靠性命令 `runtime\\python311\\python.exe tools\\collect_posture_reliability.py
--frames 200 --output report.json` 只允许在用户明确启动时保存数值报告。
报告包含硬件、分辨率、后端、模型版本、样本数和丢帧数；图像、视频、人脸裁剪、
身份模板和向量继续禁止保存。

**后续变更要求:**
任何真实摄像头可靠性采集完成后，必须把实际 SEM/MDC 报告摘要写入
`DEVELOPMENT_LOG.md`，并单独记录硬件、分辨率、后端、丢帧和未验证项。
在此之前不得宣称已完成跨设备可靠性或外部效度验证。

**科学复核结论（2026-08-13）:**

- OSHA 的计算机工作站指南把头部大致朝前、与躯干对齐列为中性工作姿势的参考，同时明确指出即使姿势良好，长时间保持同一姿势或久坐也不健康，并建议经常改变工作姿势。这支持“明显头-躯干错位应可见”和“长期低活动应作为暴露上下文”两个方向，但不提供本项目阈值，也不支持从正面单目视频声称临床脊柱角度。
- “任何单一变量都不增长风险”不成立。修订后的契约是：普通孤立变化不构成姿态偏离；可靠且极端的单通道变化可以构成姿态证据；低轨迹活动可以小幅提高综合风险，但永远不是姿态证据。三者必须分别展示和测试。
- 当前已通过确定性合成样本与 Worker 链路测试；尚未完成真实摄像头、跨设备、受控人体试验、外部金标准或医学效度验证，因此结论只到产品逻辑一致性和可审计性，不到临床科学有效性。
